# Streamora audit — 2026-11-01

The original audit was report-only. The review follow-up fixed findings #1, #2, #3, #5, #8, #9 and #11; the other findings remain open and unchanged. Original locations below refer to the working tree after Tasks 1–3; review status notes describe the fixes. Findings are confirmed by reachable code paths unless marked **unconfirmed**; this is not an iPhone performance profile.

1. **High — ASS/SSA subtitles can execute HTML.** `js/player/subs.js:53`, `js/player/subs.js:61`, `js/player/player.js:649`.
   A viewer opening an ASS/SSA subtitle can execute attacker-controlled event handlers in the app, because that parser bypasses the SRT/VTT tag filtering and its output reaches `dangerouslySetInnerHTML` (a local parser probe confirmed that an image event handler survives).
   Fix: use one strict HTML sanitizer for every subtitle format before rendering, allowing only attribute-free formatting tags, or render subtitle text as text nodes.
   Review status: **Fixed.** ASS/SSA, SRT and VTT now pass through one escaping sanitizer that only restores attribute-free i, b, u, em, strong and br tags; executable, attributed and malformed markup is covered by `tests/subs.test.js`.

2. **High — the last playback failure never shows its error.** `js/pages/watch.js:140`, `js/pages/watch.js:150`.
   When the last candidate fails after resolution, including an unsupported-audio MKV, `onFatal` only sets `err` while `ready` remains truthy, so the user stays on the failed Player instead of seeing the error and retry actions.
   Fix: clear `ready` when no untried candidate remains, or make the error state take precedence over the Player in rendering.
   Review status: **Fixed.** The exhausted-candidate branch clears `ready`, displays the error/retry screen, and permits retrying the source; the component transition is covered by `tests/review.test.js`.

3. **Medium — a failed page import cannot be retried in place.** `js/main.js:188`, `js/main.js:209`.
   After a transient page-module failure, pressing Retry deletes the cached entry and shows a spinner indefinitely because the loading effect only depends on the unchanged route pattern.
   Fix: include an explicit retry generation in the loading effect or invoke the page loader directly from Retry.
   Review status: **Fixed.** PageHost now tracks a retry generation, so deleting a failed cache entry also reruns the loading effect; the failed-loader/retry transition is covered by `tests/review.test.js`.

4. **Medium — leaving Watch does not stop source resolution.** `js/pages/watch.js:78`, `js/pages/watch.js:107`, `js/core/tb.js:204`.
   Leaving during source search or resolution can keep requests and polling running and can even add a torrent after the viewer has left, because the Watch effects have no cleanup that cancels resolution or invalidates the generation.
   Fix: pass an AbortSignal through search and resolution, invalidate the session on unmount, and check cancellation before account mutations; the MKV engine's new detach handling only covers the media stage.

5. **Medium — explicit file choices in watch links can be ignored.** `js/pages/watch.js:91`, `js/core/tb.js:116`.
   If an addon already returned the pinned hash, a watch link's `file` and `fn` choices are ignored in favor of that candidate's fields, potentially playing another file from the same pack (filename matching also precedes episode matching).
   Fix: overlay explicit query file/filename values on the matched candidate before resolving it.
   Review status: **Fixed.** Explicit `file` and `fn` query values now overlay the matched candidate while preserving its remaining metadata; file index zero and omitted overrides are covered by `tests/review.test.js`.

6. **Medium — browser audio tracks are hidden.** `js/pages/watch.js:121`, `js/player/player.js:611`, `js/player/player.js:692`.
   A browser viewer cannot change between embedded dubs because TorBox sessions always pass `info: null` and the web audio menu only reads the old `info.details.audio` structure, even though MKV remuxing can inspect the tracks and choose one at startup.
   Fix: expose actual engine track metadata and a track-selection/restart operation to the Player, retaining VLC's existing track path.

7. **Medium — embedded MKV subtitles are unavailable in browsers.** `js/pages/watch.js:121`, `js/player/player.js:614`, `js/player/player.js:724`.
   A viewer whose MKV already contains subtitles sees only external OpenSubtitles results or “No subtitles found for this one,” because web embedded tracks still depend on absent Real-Debrid-era media info and the new conversion emits only video and audio.
   Fix: extract supported text subtitle tracks for the overlay, and explain when an image subtitle track requires the app rather than offering the obsolete burn-in path.

8. **Medium — failed Drive sync retries every 1.5 seconds.** `js/core/sync.js:293`, `js/core/sync.js:297`, `js/core/sync.js:310`.
   A signed-in phone with pending changes repeatedly retries failed sync even offline or hidden, generating unnecessary requests and work instead of waiting for connectivity; the dirty state unconditionally schedules another round after each failure.
   Fix: retain dirty data but gate retries on connectivity and visibility and use bounded exponential backoff, resetting it after a successful sync or the online event.
   Review status: **Fixed.** Sync rounds now use 5-second exponential backoff capped at 5 minutes, respect the deadline despite edits/polls, retain dirty data while offline or hidden, and reset after success or an online event; fake-clock tests in `tests/sync-retry.test.js` cover these cases and foreground resumption.

9. **Medium — slow subtitle requests can overwrite a newer choice.** `js/player/player.js:332`, `js/player/player.js:341`.
   Quickly choosing subtitle A and then B, or turning subtitles off while A loads, can show A afterward because every completed download calls `showCues` without checking whether it is still the current choice.
   Fix: use a subtitle selection generation or abort the previous fetch and ignore stale completions, including after Off and unmount.
   Review status: **Fixed.** A subtitle selection generation now suppresses stale successes and failures after a newer choice, Off or unmount, including local-file selections and delayed automatic selection; controller and Player tests cover the lifecycle in `tests/subtitle-choice.test.js` and `tests/player-review.test.js`.

10. **Medium — unconfirmed: an expired link cannot refresh in place.** `js/core/tb.js:165`, `js/player/engine.js:59`, `js/player/mkv.js:109`, `js/pages/watch.js:140`.
    If a CDN link expires during a long pause, the direct engine retries the same link and MKV retries the same UrlSource before source fallback, so a viewer can lose a playable copy despite `resolveStream` being able to mint a fresh link (the service's expiry interval and a real expiry failure were not tested).
    Fix: recognize authorization/expiry failures and re-resolve the same account file once, preserving the position, before trying a different source.

11. **Low — empty quality section in the browser's MKV settings.** `js/player/player.js:731`.
    MKV viewers see a “quality” heading with no choices because the leftover transcode UI always renders that heading on the web while `info` and `stream.hls` are both absent.
    Fix: build the list of actual quality choices first and render the section only when choices exist; remove unused modelUrl/isTc assumptions when that player work is scoped.
    Review status: **Fixed.** The quality heading and grid render only when the actual choice list is nonempty, retaining HLS choices; both branches are covered by `tests/player-review.test.js`.

12. **Low — paused subtitles keep an animation loop running.** `js/player/player.js:353`.
    A paused phone player with external subtitles still searches and allocates cue results on every animation frame despite its unchanged playback time.
    Fix: stop the loop while paused or hidden, update once on seek, and resume on playback; the size of the battery impact remains **unconfirmed** without a device profile.

The requested review also covered `js/player/native.js`, `js/lib/update.js`, `functions/api/tb/[[path]].js`, `sw.js`, `_headers`, and `.github/workflows/ios.yml`. The update check sets its ten-minute throttle before fetching and remembers Later for the session (`js/lib/update.js:50`), so frequent foregrounding does not cause a GitHub request each time. The service worker bypasses API/video traffic and the new libraries were not added to SHELL. Blur/paint cost on a real iPhone, real CDN expiry, and the iOS build workflow were not exercised; no device-performance claim or workflow failure is asserted here.

## Review validation

The separate review fixes also guard SourceBuffer operations during startup seeks, preserve a seek queued before metadata, remove the detail page's native-player import, and use neutral `webPrefs()` directly in detail and Watch. Regression tests were observed failing before each requested fix was implemented. The startup test additionally reproduced the pre-metadata seek being overwritten before that race was fixed.

- `npm test`: **46 passed, 0 failed**; `parse.js ok`, `integrations: all passed`, `TorBox MKV fallback: all passed`.
- `node tools/mkvtest.mjs`: **all eight assertions passed**, with zero console/page errors and zero fatal callbacks in the startup seek check:
  1. Resume/audio: **PASS**, 120.79s, 27,898 decoded audio bytes.
  2. Ten-second playback: **PASS**, advanced 9.21s.
  3. Far seek: **PASS**, 2068.01s.
  4. Seek back: **PASS**, 60.82s.
  5. Rapid seeks: **PASS**, 1654.74s.
  6. EOF and subsequent playback: **PASS**, one ended event.
  7. Startup cancellation, reattach and playback detach: **PASS**, zero errors.
  8. Seek to 300s immediately after src appears and before any buffered data: **PASS**, 300.72s and advancing within the 30-second limit, zero errors/fatal callbacks.
- A rendered Chrome check confirmed ASS/SRT/VTT image payloads remain inert in the DOM, and the settings menu has no empty quality heading.
- A Chrome page-import test returned HTTP 503 on the first module request; Retry issued a second request and rendered the page successfully.

The first two playback attempts stopped at assertion 1 because a newer HEVC item now leads the account list and is unsupported by this Chrome. The harness now prefers the already-existing H.264 test copy documented in the implementation plan, with the original first-MKV behavior as a fallback; no account items were added, deleted or modified. A subsequent run exposed the pre-metadata seek race at assertion 8, which was fixed and covered by a failing-then-passing unit test before the successful full rerun above.

Real iPhone behavior, non-Chrome playback, and real Google Drive outage/recovery were not exercised in this review; Drive timing and data-retention checks used mocked services and a fake clock. The five deferred audit findings remain open.
